## 一、接口分析

### 1.1 接口清单

| 序号 | 子模块 | 方法 | 路径 | 认证 | 说明 |
|:----:|--------|:----:|------|:----:|------|
| 1 | 在线用户 | GET | /monitor/online/list | 需要 | 获取在线用户列表 |
| 2 | 在线用户 | DELETE | /monitor/online/{tokenId} | 需要 | 强退在线用户 |
| 3 | 定时任务 | GET | /monitor/job/list | 需要 | 获取定时任务列表 |
| 4 | 定时任务 | GET | /monitor/job/{jobId} | 需要 | 获取定时任务详情 |
| 5 | 定时任务日志 | GET | /monitor/jobLog/list | 需要 | 获取任务日志列表 |
| 6 | 定时任务日志 | GET | /monitor/jobLog/{jobLogId} | 需要 | 获取任务日志详情 |
| 7 | 服务监控 | GET | /monitor/server | 需要 | 获取服务器状态信息 |
| 8 | 缓存监控 | GET | /monitor/cache | 需要 | 获取缓存总览信息 |
| 9 | 缓存监控 | GET | /monitor/cache/getNames | 需要 | 获取所有缓存名称 |
| 10 | 缓存监控 | GET | /monitor/cache/getKeys/{cacheName} | 需要 | 获取指定缓存的键名 |
| 11 | 缓存监控 | GET | /monitor/cache/getValue/{cacheName}/{cacheKey} | 需要 | 获取指定键的缓存值 |
| 12 | 操作日志 | GET | /monitor/operlog/list | 需要 | 获取操作日志列表 |
| 13 | 登录日志 | GET | /monitor/logininfor/list | 需要 | 获取登录日志列表 |

### 1.2 认证方式

所有接口均需携带 `Authorization: Bearer {token}` 请求头，通过 `/login` 接口获取 Token。

### 1.3 响应模型

所有接口遵循统一响应格式：
```json
{
  "code": 200,      // 200=成功, 401=未认证, 500=失败
  "msg": "操作成功",
  "rows": [...],    // 列表接口返回
  "data": {...},    // 详情接口返回
  "total": 0        // 列表接口返回总数
}
```

## 三、断言策略（四层断言）

1. **HTTP 状态码断言**：`assert resp.status_code == 200`
2. **业务码断言**：`assert data.get("code") == 200`（正常场景）或 `== 401`（未认证场景）
3. **返回字段断言**：`assert "rows" in data` / `assert "data" in data`
4. **数据类型断言**：`assert isinstance(data.get("rows"), list)`

## 四、风险分析

| 风险 | 等级 | 说明 | 应对 |
|------|:----:|------|------|
| 缓存不可用 | 低 | 缓存监控接口依赖 Redis 运行 | 测试中检测 Redis 连接状态，不可用时跳过 |
| 无在线用户 | 低 | 在线用户列表可能为空 | 正常场景断言至少返回 200，不强制要求有数据 |
| 无定时任务数据 | 中 | 若系统未配置定时任务，列表为空 | 正常场景只断言响应格式正确 |
| 接口路径变更 | 低 | RuoYi 版本升级可能改变路径 | 路径配置化，集中在 client.py 中管理 |

## 六、运行方式

```bash
# 运行全部系统监控测试
pytest tests/monitor/ -v

# 运行指定子模块
pytest tests/monitor/test_online.py -v
pytest tests/monitor/test_cache.py -v

# 按标记筛选
pytest tests/monitor/ -m smoke -v

# 生成 Allure 报告
pytest tests/monitor/ --alluredir=allure-results
allure serve allure-results
```

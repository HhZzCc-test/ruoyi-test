# 认证模块 API 测试方案

## 一、接口来源

基于 `http://localhost:18080/v3/api-docs` 的 Swagger/OpenAPI 文档。

## 二、接口分析

| 接口 | 方法 | 路径 | Tag | 说明 |
|------|------|------|-----|------|
| 验证码 | **GET** | `/captchaImage` | `captcha-controller` | 获取登录验证码图片及uuid |
| 登录 | **POST** | `/login` | `sys-login-controller` | LoginBody{username, password, code, uuid} |
| 注册 | **POST** | `/register` | `sys-register-controller` | RegisterBody{username, password, code, uuid} |
| 路由 | **GET** | `/getRouters` | `sys-login-controller` | 获取用户路由菜单（需Token） |
| 用户信息 | **GET** | `/getInfo` | `sys-login-controller` | 获取当前用户信息（需Token） |

### 请求参数

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| username | string | 是 | 用户名 |
| password | string | 是 | 密码 |
| code | string | 是 | 验证码 |
| uuid | string | 是 | 验证码唯一标识 |

### 响应模型 AjaxResult

| 字段 | 类型 | 说明 |
|------|------|------|
| code | integer | 业务码（200=成功） |
| msg | string | 提示信息 |
| data | object | 返回数据 |
| token | string | 登录成功后返回的Token |

## 四、断言设计

每个测试至少包含以下四层断言：

| 层级 | 示例 |
|------|------|
| HTTP状态码 | `assert resp.status_code == 200` |
| 业务码 | `assert data["code"] == 200` |
| 返回字段 | `assert "token" in data` |
| 数据类型 | `isinstance(data["uuid"], str)` |

## 六、运行方式

```bash

pytest tests/ -v -m smoke                 # 冒烟测试
pytest tests/ --alluredir=allure-results  # 生成Allure报告
allure serve allure-results               # 查看报告
```

## 七、风险分析

| 风险项 | 等级 | 说明 |
|--------|------|------|
| 验证码绕过 | **高** | 后端未严格校验uuid与code匹配可被绕过 |
| 暴力破解 | **高** | 登录接口缺少频率限制 |
| 并发注册 | **中** | 并发注册同名用户可能绕过唯一性校验 |
| Token伪造 | **高** | Token签名算法强度直接影响安全性 |
| 信息泄露 | **中** | `/getInfo` 返回字段需控制，不应暴露敏感信息 |
| 参数注入 | **中** | 用户名/密码参数可能被SQL注入或XSS攻击 |
| 会话固定 | **低** | Token需在服务端有失效机制 |
